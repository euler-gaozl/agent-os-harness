# 使用模型原生长度的执行器候选

`dsh-source-639ed015-native-v4` 沿用固定 DSH AgentLoop、resident 历史释放和工作状态协议。
新构建位于 `.work/native-candidate`；不覆盖 v1/v2/v3，不改变上游原始文件。
尚未接入正式 Runtime/Worker，不能执行正式任务，也不是完整长度能力验收。

## 配置与回执

只接受 Registry 已解析并冻结的 `model_limits`，校验模型、上下文窗口、输出和元数据身份。
普通回答、压缩摘要都使用冻结的官方最大输出，取消历史 4096/32768/摘要 2048 限制。
上限是允许生成的范围，不要求模型填满；输入与输出共享供应商窗口。

format2 的 `provider_context_rejected` 必须来自已保存的供应商 HTTP 400，包含请求和响应摘要、
冻结长度及 `not_sent:false`。仅这类确定结果进入 DSH 的上下文恢复钩子；旧 format1 的预发送
估算拒绝、未知网络结果、401/500 不接受为此结果。监督器尚待实现真实回执校验，
本候选不把 Node 收到一份夹具写成供应商已验证。

保留 DSH 的两次溢出恢复边界、压缩不再重试、落盘屏障和当前工作状态回查。
摘要必须减少待保存表示的字节量；这项检查不是模型 tokenizer，也不证明事实完整性。
供应商拒绝后无法有效压缩时，任务明确失败，原始证据仍应由 Runtime 留存。

## 容量与验证边界

大文本检查发现原 resident 16 MiB 阈值会在合法大文本响应后失败；native 独立构建将事件队列、
resident 历史及相关投影容量设为 64 MiB，工作状态传输允许 16 MiB，桥接帧 127 MiB。
这是防止进程无限占用的字节界限，不能写成“无限输入输出”。核心补丁前后摘要进入 manifest；
旧 resident 变换不改。监督器的 HTTP/帧和 Node 内存配置仍必须同步实现、测量后再部署。

本机真实 Node/DSH、合成监督器和模型回执共 17 项通过，包含大于旧上限的输出、实际用量反馈、
确定拒绝后压缩、无效压缩/未知传输阻断、回执前后强杀重放，以及 4,500,000 字节输入和
5,250,000 字节输出的完整传递。合成字节数不代表真实模型 token 数，也没有调用付费模型。
初次压力夹具缺少足够可压缩的历史、随后大文本触发旧 resident 阈值，两次失败记录保留。
